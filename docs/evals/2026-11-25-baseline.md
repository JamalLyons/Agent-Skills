# Skill eval baseline — 2026-11-25

First full with-skill vs without-skill comparison across every portable eval case (23 skills, 59 cases). Use it as the reference point for later runs.

## Method

- **Runs:** one fresh headless Claude Code session per variant per case, model `claude-sonnet-5-5`, via a local adapter equivalent to [`scripts/adapters/claude-code.sh`](../../scripts/adapters/claude-code.sh) with `bypassPermissions` in a disposable workspace. Network, `gh`, push, publish, package installs, `caffeinate` and `kill` were denied. Installed user skills were disabled (`--disable-slash-commands`) so the without-skill baseline stays clean.
- **Grading:** blind A/B packets (`evaluate.py blind`), one fresh `claude-opus-5-5` session per case, which split `expected_output` into 3–8 assertions and graded each pass/partial/fail with evidence. Notes were recorded with `evaluate.py grade --label` and summarized with `evaluate.py report`.
- **Snapshot:** trunk at the merge of #17 (skills as of `2708c66`).

## Findings

- **21 of 23 skills beat no skill; handoff tied and create-workforce-epic lost.** The largest gains are on skills that encode a procedure or boundary the model does not default to: skill-retro, wizard, plan-next-epic-tasks, release, research, ship.
- **Near-zero gain (≤4 points):** handoff, code-review, domain-modeling, improve-codebase-architecture. The base model already scores 93–100% on these cases, so the cases are likely too easy to discriminate. Add harder cases before judging these skills.
- **create-workforce-epic −5:** it asked for approval that had already been given, and its plan file left C1 `covered_by` empty because the schema had no way to credit an existing issue. Fixed in the same PR as this report.
- **caffeine-time repeat-invocation:** when the user said a timer was running but no pidfile existed, the skill fell through to starting a new timer. Fixed in the same PR; the new `claimed-timer-missing` case guards it.
- **Cost:** with-skill runs used about 1.3–2.7× the output tokens (tdd used fewer) and took a few seconds longer. The absolute increase is small (about 200–1,000 tokens per run).

## Limits

- One run per variant per case and one grader model: small deltas are within noise.
- The grader saw denied commands (`permission_denials` in `result.json`) and sometimes counted an attempted-but-denied action against the run.
- 51 of 59 cases were graded on a retry after the grader hit an API rate limit; grading prompts were identical.
- Raw run directories were kept locally, not committed.
